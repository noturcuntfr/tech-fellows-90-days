
# Day 06 - Semantic HTML & Accessibility Audit

## Project Reviewed
Tech Fellows - Days 1 to 5 website

## Accessibility Checks

| Check | Finding | Fix / Next Action |
|---|---|---|
| Semantic regions | Pages use header, nav, main and footer. | Keep the structure consistent. |
| Heading hierarchy | Checked that each page has one main h1. | Keep headings in logical order. |
| Image alt text | Checked profile image descriptions. | Use meaningful alt text for informative images. |
| Link purpose | Reviewed navigation link descriptions. | Use descriptive link text. |
| Form labels | Checked labels and matching input IDs. | Correct any mismatched labels. |
| Keyboard focus | Tested navigation using Tab and Shift+Tab. | Keep all interactive elements keyboard accessible. |
| Table structure | Checked caption, headings and table rows. | Maintain meaningful table headers. |
| Narrow-screen usability | Tested pages in a narrow browser window. | Keep content readable and usable. |

## Reflection Questions

### 1. Which accessibility issue did I find first?
I first checked whether the form labels were properly connected
to their input fields.

### 2. What changed when I tested the page without a mouse?
I learned how to navigate links and form controls using only
the keyboard.

### 3. How did I decide what alt text to write?
I described the useful information shown in the image instead
of writing unnecessary details.

### 4. Which two checks will I repeat on every future project?
I will always check heading hierarchy and keyboard navigation.

## What I Learned
I learned that semantic HTML makes websites easier to
understand and that accessibility should be considered
while building every webpage.
